# єСвітло — графіки відключень на сьогодні та завтра

Вебсайт і Telegram-бот для перегляду графіків відключень в Україні. Сервер регулярно отримує дані джерела, зберігає останній відомий графік і роздає його сайту та API. Клієнти читають графіки з API єСвітло.

## Застосунок для телефона

Відкрийте [єСвітло](https://yesvitlo.pp.ua/) на телефоні.

- **Android, Chrome** — у меню ⋮ виберіть «Установити застосунок» або «Додати на головний екран».
- **iPhone, Safari** — натисніть «Поділитися» → «На початковий екран».

Відкрийте потрібний регіон з інтернетом принаймні один раз. Під час втрати зв'язку застосунок покаже останній збережений графік на сьогодні або завтра з попередженням. Сповіщення надходять через Telegram. Для встановлення на телефон сайт має бути доступний через HTTPS.

[Відкрити сайт](https://yesvitlo.pp.ua/) · [Telegram-бот](https://t.me/dtekschedule_bot) · [API](docs/api.md) · [Розгортання](docs/deployment.md) · [Будова проєкту](docs/architecture.md)

## Можливості

- Сьогодні та завтра одночасно, усі 12 підчерг або одна вибрана група.
- Київський час, поточний момент на графіку та залишок планових відключень.
- Порівняння з попередньою збереженою версією: зелений номер зміненої групи та суцільна рамка за типом зміни на змінених півгодинних інтервалах.
- Пам'ять вибраної групи у браузері та окрема підписка на групу в Telegram.
- Telegram надсилає картинки графіків після зміни даних, з урахуванням вибраної групи.
- Червоне попередження про екстрені відключення з повідомленням оператора і назвами територій, які в ньому зазначені.
- API готових графіків: короткі часові інтервали, об'єднання однакових груп, фільтри, ETag та час наступного оновлення кешу.
- Необов'язкове чергування перевірок ДТЕК напряму та через ізольований PPTP VPN-проксі.
- Збереження отриманих даних між перезапусками та попередження, коли джерело недоступне.

## Швидкий запуск у Docker

Потрібні Docker Engine, плагін Docker Compose і доступ до джерел графіків. Образ містить Node.js та системний Chromium для сторінок, які потребують браузерного завантаження.

```sh
git clone https://github.com/Daniell2019UKR/esvitlo.git
cd esvitlo
cp .env.example .env
# За потреби змініть REGION, PORT та параметри Telegram у .env.
docker compose up -d --build
docker compose ps
```

Відкрийте [localhost:3000](http://localhost:3000/). Якщо змінено `PORT`, використовуйте відповідний порт. На першому запуску графік з'явиться після успішного отримання даних оператора.

```sh
docker compose logs --tail 50 web
docker compose down
```

Звичайний `docker compose down` зберігає том з даними. Для зупинки не додавайте `--volumes`, якщо хочете залишити кеш графіків і налаштування бота.

## Налаштування

Робочі значення зберігаються у локальному `.env`, створеному з [прикладу](.env.example). Після зміни змінних середовища виконайте `docker compose up -d`, щоб Compose перестворив контейнер з новими значеннями.

| Змінна | Призначення |
| --- | --- |
| `REGION` | Регіон за замовчуванням. `o` — Одеська область; `k` — Київ; `kr` — Київська область; `dn` — Дніпропетровська; `d` — Донецька. Типово `o`. |
| `PORT` | Порт доступу до сайту на хості, типово `3000`. Усередині Compose застосунок слухає `3000`. |
| `DATA_DIR` | Каталог стану застосунку. Compose задає `/app/data` і підключає постійне сховище. |
| `PUBLIC_URL` | Посилання на сайт у повідомленнях бота, наприклад `https://yesvitlo.pp.ua`. |
| `POLL_INTERVAL_SECONDS` | Інтервал перевірок джерел у секундах: типово `120`, допустимий діапазон `30–3600`. |
| `DTEK_PROXY_URL` | Необов'язкова адреса HTTP-проксі для VPN-маршруту. Якщо задана, перевірки чергуються: напряму, через проксі, напряму тощо. |
| `DTEK_PROXY_HEALTH_URL` | Необов'язковий маршрут перевірки VPN-проксі; у VPN Compose — `http://vpn-proxy:8889/health`. |
| `VPN_RETRY_SECONDS` | Пауза перед повторною перевіркою недоступного VPN, типово `60` секунд, мінімум `10`. |
| `TELEGRAM_BOT_TOKEN` | Токен бота від BotFather. Порожнє значення вимикає Telegram. |
| `TELEGRAM_CHAT_IDS` | Початкові chat IDs через кому для серверного налаштування підписок. |
| `TELEGRAM_GROUPS` | Початкове обмеження груп, наприклад `1.1,1.2`. Порожнє значення означає всі групи. |
| `CHROMIUM_PATH` | Шлях до системного Chromium. У Docker вже заданий. Для локального запуску можна залишити порожнім і встановити браузер Playwright. |

Не додавайте `.env`, паролі VPN, токен Telegram або файли стану до Git. Застосунок не передає ці значення у браузер чи публічний API.

Якщо VPN-маршрут недоступний, сервер тимчасово виключає його з чергування та продовжує перевірки напряму. Повторна перевірка доступності відбувається після паузи; після відновлення VPN чергування може продовжитися. Налаштування ізольованого PPTP-контейнера описане в [інструкції розгортання](docs/deployment.md#необовязковий-pptp-vpn).

## Як читати графік

| Позначення | Значення |
| --- | --- |
| Червоний інтервал | За опублікованим планом світла немає. |
| Зелений інтервал | За опублікованим планом світло є. |
| Сірий інтервал | Джерело не надало розпізнаваних даних. Це не гарантія наявності світла. |
| Приглушений інтервал | Ця частина сьогоднішнього дня вже минула. |
| Зелена вертикальна лінія | Поточний київський час. |
| Зелений номер і точка | Графік групи відрізняється від попередньої збереженої версії. |
| Кольорова рамка | Червона — додане відключення, зелена — відновлений інтервал зі світлом, сіра — дані зникли. |

Наведення на інтервал показує дату, групу, час, стан і відмітку зміни. Для сьогодні підсумок праворуч враховує лише залишок доби, зокрема частину поточного півгодинного інтервалу. Для завтра підсумовується повний день.

Зелений колір показує план оператора, а не виміряний стан електропостачання за конкретною адресою. Аварійні й екстрені відключення можуть відбуватися поза графіком.

### Екстрені відключення

Червона плашка призначена для актуального оголошення оператора про екстрені відключення. У ній показується текст джерела, щоб зберегти обмеження за районами, містами чи іншими територіями. Номер групи сам по собі не визначає район, тому повідомлення не фільтрується за вибраною підчергою.

Сервер шукає спеціальне повідомлення джерела, а не будь-яку згадку про екстрені відключення у довідковому тексті сторінки. Якщо стан оголошення перевірити не вдалося, попереднє повідомлення має позначку застарілості. Відсутність плашки не є підтвердженням фактичної наявності електропостачання.

## Сьогодні, завтра та кеш

Дати визначаються у часовій зоні `Europe/Kyiv`, незалежно від часової зони браузера або сервера. Після опівночі вчорашній блок зникає, а вчорашнє «завтра» стає «сьогодні».

Парсер читає всі дати з `DisconSchedule.fact.data`. Якщо в новій відповіді є лише завтра, раніше отримане сьогодні зберігається до завершення доби. Якщо джерело тимчасово прибрало один із днів, сайт позначає його як збережений графік. Повністю нерозпізнаний день не затирає відомий графік. Якщо даних ще не було, показується очікування публікації; прогнозний тижневий графік не видається за добовий.

При помилці джерела остання успішна версія залишається доступною з попередженням. Перевіряйте час отримання даних, особливо під час змін режиму відключень.

Вибір «Моя група» зберігається в `localStorage` цього браузера. Він відновлюється після перезавантаження сторінки, але не синхронізується між пристроями чи з Telegram. Якщо браузер заборонив локальне сховище, вибір працює лише в поточній відкритій сторінці.

## Покриття та джерела

Каталог охоплює 22 області та Київ. Для Дніпропетровщини окремо доступні черги ДТЕК і ЦЕК. Список кодів повертає [каталог API](https://yesvitlo.pp.ua/api/v1/regions). Для Донецької області використовується сайт ДТЕК. Херсонська, Луганська області та Крим поки не підключені.

Сервер читає сторінки ДТЕК напряму, а також нормалізує добові JSON-дані [Коли Світло](https://github.com/retro20201/svitlo-mirror). Резервні джерела для частини областей — [OE_OUTAGE_DATA](https://github.com/yaroslav2901/OE_OUTAGE_DATA) та, для Вінниччини, [SvitloPulse](https://svitlopulse.andrewboyko.name/api/). Перевірки Вінниччини через SvitloPulse кешуються на 10 хвилин. За відсутності графіка в джерелах єСвітло показує збережений графік із попередженням, якщо він є. Тижневі шаблони не використовуються як добові графіки.

## API та інтеграції

Сервер надає вже нормалізовані графіки. Запити до API читають кеш і не запускають парсинг джерел, тому кількість відвідувачів та зовнішніх інтеграцій не збільшує частоту звернень до джерела.

- [Опис API, фільтри, статуси та правила оновлення](docs/api.md).
- `/api/v1/schedules` — версійований API для зовнішніх клієнтів; типово повертає компактні інтервали й об'єднує групи з однаковими графіками. Підтримує `region`, `date`, `group`, `format=compact|slots`.
- `/api/schedule` — дані та службова інформація для власного вебінтерфейсу.
- `/health` — перевірка роботи HTTP-сервера, відповідь `ok`. Цей маршрут не підтверджує доступність джерел.

```sh
curl 'https://yesvitlo.pp.ua/api/v1/schedules?group=1.1'
curl 'https://yesvitlo.pp.ua/api/v1/schedules?group=1.1&format=slots'
curl 'https://yesvitlo.pp.ua/api/v1/schedules?region=k&group=60.1'
```

У типовій відповіді `off: [["08:00", "11:30"]]` означає планове відключення `08:00–11:30`. `unknown`, якщо присутній, містить інтервали без даних; решта часу має плановий стан «світло є». `format=slots` повертає початкові масиви з 48 значень `true` / `false` / `null` на групу.

Регіон і черга зберігаються у браузері. Сповіщення беруться зі сторінки оператора вибраного регіону.

## Telegram

У приватному чаті `/reminder 60,15` вмикає нагадування за годину і за 15 хвилин до планового відключення. `/restore 30,5` вмикає нагадування до відновлення світла. Обидві команди приймають до 10 значень від 1 до 180 хвилин. Щоб налаштувати окрему локацію, додайте її номер після списку (`0` — основна, решта — додані через `/reminder_add`). Значення `off` вимикає нагадування, а `default` повертає загальне налаштування для конкретної локації. Звук для кожного типу можна змінити через `/notifications`.

Команда `/address Населений пункт | Вулиця | Будинок` пропонує чергу, якщо оператор підтримує пошук. Вибір потрібно підтвердити. Команда `/group` відкриває ручний вибір черги.

Команда `/region` відкриває вибір регіону. У груповому чаті змінити регіон може адміністратор. Бот надсилає сповіщення для вибраного регіону.

Додайте [бота до групи](https://t.me/dtekschedule_bot?startgroup=setup) і дозвольте йому надсилати повідомлення та фото. Адміністратор або власник чату відкриває `/region@dtekschedule_bot`, вибирає регіон чи оператора й натискає потрібну чергу. Команда `/group@dtekschedule_bot` змінює чергу в поточному регіоні. Після зміни регіону потрібно вибрати чергу знову. Будь-який учасник може отримати графіки через `/schedule@dtekschedule_bot` раз на 30 секунд для всього чату. Адміністратор може вимкнути автоматичні сповіщення через `/stop@dtekschedule_bot`. Вибір у груповому чаті зберігається окремо від особистих підписок.

Бот домашнього розгортання: [@dtekschedule_bot](https://t.me/dtekschedule_bot). Для власної установки створіть окремого бота у [BotFather](https://t.me/BotFather) і задайте його токен у `.env`. Користувач має сам відкрити бота та натиснути **Start**: бот не може почати приватну розмову лише за Telegram username.

Налаштування групи в боті належить конкретному чату й зберігається окремо від фільтра сайту. Оновлення графіка та поява нової дати є зміною; зміна лише часу публікації не повинна створювати дубль повідомлення.

| Команда або повідомлення | Дія |
| --- | --- |
| `/start` | Почати або відновити підписку. Новому користувачеві бот пропонує вибрати групу. |
| `/group` | Показати кнопки вибору групи всередині повідомлення бота. |
| `/group 1.1` або `1.1` | Запам'ятати групу `1.1` для цього чату. |
| `Усі групи` | Вибрати графіки всіх груп. |
| `/schedule` | Отримати картинки наявних графіків сьогодні й завтра з кешу. Не запускає новий парсинг. |
| `/notifications` | Вибрати режим «Зі звуком», «Без звуку» або «Вимкнено» для кожного типу. У групі налаштування змінює адміністратор. |
| `/stop` | Вимкнути підписку та прибрати відкладені повідомлення цього чату. |

Після зміни графіка бот надсилає окрему картинку для кожного зміненого дня. Для підписки на одну групу зміна чужих груп не створює повідомлення. Підписки, черга відправлення та позиція читання Telegram updates зберігаються у `DATA_DIR/telegram.json`. Не видаляйте цей файл при оновленні контейнера. При помилці доставки повідомлення лишається у черзі для повторної спроби; рідкісний дубль можливий при збої між прийняттям повідомлення Telegram і записом стану на диск.

Вибір групи відбувається inline-кнопками під повідомленням, а не постійною клавіатурою введення. Після натискання бот запам'ятовує вибір і замінює це повідомлення підтвердженням, прибираючи кнопки. Щоб змінити групу, надішліть `/group` знову.

## Розробка та перевірка

Потрібен Node.js 24 або новіший.

```sh
npm ci
npx playwright install chromium
cp .env.example .env
npm start
```

```sh
npm test
node scripts/verify-ui.mjs
```

`npm test` запускає тести серверної логіки. Перевірка інтерфейсу запускає тимчасовий сервер і Chromium з тестовим API та записує знімки в `artifacts/`. `UI_URL` дозволяє перевірити інше розгортання, а `CHROMIUM_PATH` — використати встановлений браузер. Тестові дані API підставляються лише в браузері перевірки.

Подробиці конфігурації Docker, резервних копій та домашнього розгортання: [docs/deployment.md](docs/deployment.md).
