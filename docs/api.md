# API готових графіків

API читає останній збережений результат серверної перевірки джерела. Жоден GET-запит клієнта не запускає нове отримання чи парсинг сторінки джерела.

API приймає до 120 запитів за календарну хвилину від однієї IP-адреси і до 2400 сумарно. Якщо ліміт вичерпано, відповідь `429` містить `Retry-After` у секундах. Параметри `date`, `group` і `format` можна вказати по одному разу.

Базова адреса API — `https://yesvitlo.pp.ua`. Для власного розгортання підставте його адресу.

## Отримати графіки

```http
GET /api/v1/schedules
```

```sh
curl -i 'https://yesvitlo.pp.ua/api/v1/schedules'
curl -i 'https://yesvitlo.pp.ua/api/v1/schedules?region=o&group=1.1'
curl -i 'https://yesvitlo.pp.ua/api/v1/schedules?date=2026-11-14&group=1.1'
curl -i 'https://yesvitlo.pp.ua/api/v1/schedules?region=o&group=1.1&format=slots'
curl -i 'https://yesvitlo.pp.ua/api/v1/schedules?region=k&group=60.1'
```

Дата в останньому прикладі ілюстративна: замініть її на сьогодні або завтра за київським часом.

| Параметр | Формат | Поведінка |
| --- | --- | --- |
| `date` | Календарна дата `YYYY-MM-DD` | Залишити один опублікований день. Без параметра повертаються всі наявні активні дні. |
| `group` | Наприклад, `1.1` або `60.1` для Києва | Підчерга вибраного регіону. Без параметра повертаються всі групи. |
| `format` | `compact` або `slots` | Типово `compact`: часові інтервали та спільні профілі груп. `slots` повертає сумісний формат із 48 значеннями на групу. |

Каталог `GET /api/v1/regions` повертає `defaultRegion` і масив `regions` із полями `code`, `name` та `source`. Передайте код із каталогу, наприклад `region=mykolaiv`, у запиті графіка. Без параметра застосовується `REGION`. Графіки та оголошення мають окремий кеш для кожного регіону. У разі `503` відповідь теж містить поле `emergency`. Історичного архіву цей маршрут не надає: активне вікно — сьогодні та завтра, а не всі колись отримані дати.

### Компактна відповідь за замовчуванням

Сусідні півгодинні відключення об'єднані в інтервали, а групи з однаковим графіком — в один профіль. Приклад успішної відповіді; часи та інтервали наведені лише як приклад:

```json
{
  "version": 1,
  "format": "compact",
  "region": "o",
  "timeZone": "Europe/Kyiv",
  "generatedAt": "2026-11-13T18:00:00.000Z",
  "checkedAt": "2026-11-13T18:02:00.000Z",
  "lastSuccess": "2026-11-13T18:02:00.000Z",
  "stale": false,
  "error": null,
  "refreshIntervalSeconds": 120,
  "nextRefreshAt": "2026-11-13T18:04:00.000Z",
  "days": [
    {
      "date": "2026-11-13",
      "schedules": [
        {
          "groups": ["1.1", "1.2"],
          "off": [["08:00", "11:30"], ["18:00", "20:00"]],
          "unknown": [["00:00", "01:00"]]
        }
      ]
    }
  ],
  "retainedDates": [],
  "emergency": {
    "active": false,
    "message": null,
    "areas": [],
    "checkedAt": "2026-11-13T18:02:00.000Z",
    "stale": false
  },
  "source": "https://www.dtek-oem.com.ua/ua/shutdowns"
}
```

| Поле | Значення |
| --- | --- |
| `version` | Версія контракту API, зараз `1`. |
| `format` | Обраний формат графіка: `compact` або `slots`. |
| `region` | Код регіону цього екземпляра. |
| `timeZone` | Часова зона календарних дат і позицій графіка. |
| `generatedAt` | Час отримання поточної версії графіка сервером. Не обов'язково дорівнює останній перевірці. |
| `checkedAt` | Час останньої спроби отримати дані джерела. |
| `lastSuccess` | Час останнього успішного отримання даних. |
| `stale` | Ознака застарілості даних. Не приховуйте її при використанні кешу. |
| `error` | Повідомлення про помилку джерела або `null`. |
| `refreshIntervalSeconds` | Налаштований інтервал перевірок джерела. |
| `nextRefreshAt` | Запланований час наступної перевірки, а не гарантія появи нового графіка. |
| `days` | Наявні нормалізовані дні після застосування фільтрів. |
| `retainedDates` | Дати, збережені з попередньої відповіді, бо остання відповідь джерела їх не містила. |
| `emergency` | Стан оголошення про екстрені відключення, описаний нижче. |
| `source` | Посилання на сайт оператора регіону. |
| `dataSource` | Джерело отриманого графіка. Може вказувати на агрегатор. |

### Як читати `compact`

`days[].schedules` — список різних добових профілів. Поле `groups` усередині профілю перелічує всі групи з точно однаковими інтервалами. Однакові профілі об'єднуються лише в межах однієї дати. Фільтри `date` і `group` застосовуються до цього об'єднання, тому `?group=1.1` повертає лише вибрану групу.

| Поле профілю | Значення |
| --- | --- |
| `groups` | Групи, до яких застосовується цей профіль. |
| `off` | Інтервали планових відключень. Порожній масив означає, що відомих відключень немає. |
| `unknown` | Інтервали без розпізнаваних даних. Поле відсутнє, якщо таких інтервалів немає. |

Інтервал `['08:00', '11:30']` означає відключення від `08:00` включно до `11:30` не включно. Останній інтервал може закінчуватися на `24:00`. Межі мають півгодинний крок, а сусідні інтервали одного стану об'єднуються.

Час, який не входить ані до `off`, ані до `unknown`, має плановий стан «світло є». Не ігноруйте `unknown`: відсутність відключення в `off` ще не означає відомий стан, якщо цей час є в `unknown`. Наприклад, профіль із `off: []` та `unknown: [['00:00', '24:00']]` означає відсутність даних за всю добу, а не гарантоване світло.

Усі часи належать даті `date` у `Europe/Kyiv`. Це добовий план оператора, а не вимірювання фактичного електропостачання.

### Сумісний формат `slots`

Запит `GET /api/v1/schedules?format=slots` залишає ті самі метадані та повертає `format: 'slots'`. Замість `days[].schedules` кожен день містить `days[].groups`, де ключ — номер групи, а значення — 48 півгодинних станів. Цей формат зберігає початкову структуру масивів для наявних інтеграцій.

Кожна група — масив із 48 елементів:

- індекс `0`: `00:00–00:30`;
- індекс `1`: `00:30–01:00`;
- індекс `47`: `23:30–24:00`.

`true` означає планову наявність світла, `false` — планове відключення, `null` — невідомий стан. Не перетворюйте `null` на `true`: це приховає відсутність даних.

Інтервали належать даті `date` у `Europe/Kyiv`. Масив є добовою таблицею оператора, а не телеметрією мережі чи UTC-історією фактичних відключень.

### Екстрені відключення

`emergency.active` має три стани: `true` — знайдено оголошення; `false` — оголошення не активне у розпізнаній відповіді джерела; `null` — визначити стан не вдалося. `message` містить текст оператора, `areas` — розпізнані назви територій, якщо вони є.

Перелік `areas` може бути порожнім навіть за активного оголошення: повідомлення може стосуватися всього регіону або містити географію, яку автоматично не вдалося виділити. Для відображення обмежень за територіями використовуйте насамперед повний `message`. Номер групи не дозволяє надійно визначити район.

`emergency.checkedAt` указує останню успішну перевірку стану оголошення, `emergency.stale` — чи доводиться використовувати збережений стан. Зберігайте цю інформацію у своєму інтерфейсі. Планові інтервали не гарантують електропостачання під час екстреного режиму.

## Частота оновлення та HTTP-кеш

Типовий серверний інтервал для ДТЕК — 300 секунд (`DTEK_POLL_INTERVAL_SECONDS`), для інших регіонів — 120 секунд (`POLL_INTERVAL_SECONDS`). Обидві змінні приймають значення від 30 до 3600 секунд. Запити клієнтів читають серверний кеш.

API повідомляє час наступної перевірки через `nextRefreshAt` і надсилає заголовки `Cache-Control`, `ETag` та `Retry-After`. `max-age` відповідає часу до наступного запланованого оновлення. Для клієнта достатньо запитувати дані після цього часу; безперервне опитування не прискорює появу нового графіка.

Для перевірки змін передавайте отриманий `ETag` у `If-None-Match`:

```http
GET /api/v1/schedules?group=1.1
If-None-Match: "значення-з-попередньої-відповіді"
```

Якщо представлення не змінилося, сервер поверне `304 Not Modified` без JSON-тіла. Використайте раніше збережену відповідь і дотримуйтеся нових заголовків кешування.

Це інтервал актуалізації спільного кешу, а не ліміт запитів на користувача. `Retry-After` допомагає запланувати повторне звернення; сам по собі він не означає помилку `429`.

## Статуси

| HTTP | Значення та дія клієнта |
| --- | --- |
| `200` | Збережений графік доступний. Перевірте `stale`, `error` та часи перед відображенням як актуального. |
| `304` | Для переданого `If-None-Match` немає нової версії. Використайте локальний кеш. |
| `400` | Неправильна дата або номер групи. Виправте параметри. |
| `400` | Невідомий `format`. Використайте `compact` або `slots`. |
| `404` | Коректно заданої дати немає серед доступних графіків. Не трактуйте це як «відключень немає». |
| `503` | У вибраному регіоні немає збереженого графіка на сьогодні або завтра. Поле `nextRefreshAt` указує час наступної перевірки. |

При тимчасовій недоступності джерела раніше отриманий графік може повертатися з `200`, але з ознакою застарілості та помилкою. Помилка джерела не повинна змушувати клієнта показувати всі інтервали зеленими.

## CORS і службові маршрути

Версійований API повертає `Access-Control-Allow-Origin: *`, щоб його могли читати зовнішні вебклієнти, які мають мережевий доступ до сервера. `ETag` і `Retry-After` доступні JavaScript-клієнту через `Access-Control-Expose-Headers`; для умовного запиту з `If-None-Match` підтриманий OPTIONS preflight. Доступні `GET`, `HEAD` та `OPTIONS`. API не повертає токен Telegram, пароль VPN, підписки або чергу повідомлень.

`/api/schedule` призначений для власного сайту й містить додаткові поля стану, поточну/попередню версії та метадані інтерфейсу. Для нових інтеграцій використовуйте `/api/v1/schedules`.

`/health` повертає `ok`, коли працює HTTP-сервер. Успішний healthcheck не гарантує актуальності графіка або доступності зовнішніх сервісів.

## Визначення черги за адресою

У відповіді `GET /api/v1/regions` поле `addressLookup` указує, чи доступний пошук для оператора.
Надішліть адресу в тілі `POST /api/v1/address-queue` з типом `application/json`. Підтримується також CORS-запит `OPTIONS`.

```json
{"region":"o","city":"Одеса","street":"Назва вулиці","house":"10А"}
```

Відповідь містить `status`, масив `groups` і, за наявності, посилання `source`.

| HTTP | Результат |
| --- | --- |
| `200` | `ok` з однією або кількома чергами. Запропонуйте користувачу підтвердити вибір. |
| `200` | `not_found`, `unsupported` або `unavailable` з порожнім `groups`. Запропонуйте ручний вибір. |
| `400` | Неправильні поля, невідомий регіон або невалідний JSON. |
| `405` | Непідтримуваний метод. |
| `413` | Тіло запиту перевищує 2 КіБ. |
| `415` | Непідтримуваний тип або кодування вмісту. |
| `429` | Перевищено ліміт. Час до повтору в секундах повертається в `Retry-After`. |

Передавайте всі чотири поля рядками до 100 символів. Пошук зіставляє конкретну адресу, тому його слід викликати після підтвердження введення. Ліміти пошуку діють окремо від API графіків. Відповіді мають `Cache-Control: private, no-store`. [Джерела операторів](address-sources.md).

## Аварійні відключення за адресою

`POST /api/v1/address-outage` приймає ті самі поля та використовує спільний ліміт адресних запитів. Поле `outageLookup` у каталозі регіонів показує, чи є цей пошук у конкретного оператора.

`active` повертає підтверджену оператором аварію, причину (`reason`), час початку (`startedAt`) та орієнтовний час відновлення (`estimatedRestoration`). Час передається як текст оператора, а порожнє поле означає відсутність відповідної інформації. `no_emergency` означає, що оператор не повідомив про аварію. Для невідомого будинку, неоднозначної адреси, недоступного або непідтримуваного джерела повертаються `not_found`, `ambiguous`, `unavailable` або `unsupported` відповідно.
